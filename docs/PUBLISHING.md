# Publishing notes

How one source becomes a printed book. Verify every figure below with the chosen
printer before locking; templates and limits change.

## One source, three outputs

- HTML: the website. Language tabs, search, copy buttons.
- PDF for print: Quarto renders LaTeX (XeLaTeX), so trim size, margins, running
  heads, fonts and widow control are set in `shared/quarto-common.yml` and
  `shared/tex/print.tex`. This is the route a publisher or print-on-demand
  service can take as is.
- EPUB: for e-readers. Code blocks wrap; tabs become sequential sections.

## Print checklist

1. Trim size. Default 7.5 x 9.25 in (common for technical books). Common
   alternatives: 6 x 9 in, 7 x 10 in. Change in one place.
2. Page count sets spine width, so the cover is built last. Print-on-demand
   services publish a spine calculator by paper stock and page count.
3. Margins: inner margin grows with page count so text stays out of the gutter.
4. Fonts embedded; images at 300 dpi or vector; greyscale-safe code listings
   (no meaning carried by colour alone).
5. Front matter: half-title, title page, copyright page (rights, edition, ISBN),
   contents, preface. Back matter: references, index.
6. ISBN: one per format (paperback, hardcover, EPUB). Bought through the national
   ISBN agency; the publisher or printer may assign their own.
7. Index: build from `\index{}` entries (Quarto raw LaTeX) and run `makeindex`.
8. Cover: separate file (front, spine, back, bleed), not generated by Quarto.
9. Proof: order a physical copy before approving.

## Soft cover versus hard cover

The interior PDF is the same. The cover file differs (hardcover wraps and needs
a larger bleed and a hinge allowance). Print-on-demand services supply a
template for each binding by trim size and page count.

## Shared across books

Everything under `shared/` is common. A book overrides only what differs
(title, subtitle, cover, trim size if wanted) in its own `_quarto.yml`.
